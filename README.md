# 🎨 WagleWagle Studio - AI 인터랙티브 미디어월 & 드로잉 스튜디오 (오프라인 10대 연동 시스템)

외부 인터넷 연결이 없는 독립된 로컬 네트워크(단독 공유기/AP/유선 스위치) 환경에서, **호스트 노트북 1대**를 서버로 두고 **최대 10대의 노트북**이 실시간(0ms)으로 캐릭터 송출, 배경 테마 변경, 전시 운영 상태를 양방향 동기화하는 인터랙티브 미디어아트 시스템입니다.

---

## 🚀 빠른 시작 (호스트 노트북 설정)

### 1. 호스트 노트북의 로컬 사설 IP 확인
호스트(서버) 역할을 할 노트북에서 명령 프롬프트(CMD) 또는 PowerShell을 열고 아래 명령어를 실행합니다:

```bash
# Windows
ipconfig
```
- 출력 결과 중 **`IPv4 주소`**를 확인합니다. (예: `192.168.0.225` 또는 `192.168.1.10`)
- Mac/Linux인 경우 `ifconfig` 또는 `ip a`로 확인합니다.

### 2. 프로젝트 의존성 설치
프로젝트 루트 폴더(`media_wall`)에서 터미널을 열고 의존성을 설치합니다:

```bash
npm install
```

### 3. 서버 1-클릭 실행
윈도우 환경에서는 파일 탐색기에서 **`start-server.bat`** 파일을 더블클릭하거나, 터미널에서 다음 명령을 실행합니다:

```bash
# 기본 실행 (HTTP 3000번 포트 + HTTPS 3443번 포트 동시 구동)
npm run start

# 또는 SSL 인증서 자동 재생성 후 실행
npm run start:https
```

서버가 구동되면 콘솔에 아래와 같은 안내가 출력됩니다:

## 💻 10대 노트북 화면별 접속 주소 안내

동일한 로컬 Wi-Fi 또는 유선 LAN에 연결된 각 노트북의 웹 브라우저(크롬 또는 엣지 권장)에서 호스트 IP로 접속합니다:

| 역할 | 접속 URL | 설명 |
| :--- | :--- | :--- |
| **통합 메인** | `http://[호스트IP]:3000/` | 상단 탭으로 미디어월/스튜디오/관리자 전환 가능 |
| **대형 미디어월** | `http://[호스트IP]:3000/wall.html` | 빔프로젝터/LED 전광판용 전체화면 미디어아트 |
| **학생 드로잉 스튜디오** | `http://[호스트IP]:3000/draw.html` | 학생용 도안 색칠, AI 변환 및 MP4 전송 화면 |
| **마스터 관리자** | `http://[호스트IP]:3000/admin.html` | 배경 테마/도안 관리, 실시간 관제 (**비밀번호: 2326**) |

## ⚡ 10대 기기 실시간 동기화 (Socket.io) & SQLite 영구 DB

### 1. 실시간 동기화 항목
1. **캐릭터 실시간 스폰 (`character_spawn`)**:
   - 학생 노트북에서 드로잉 도안을 AI로 변환하거나 MP4 비디오를 전송하면, 0ms 지연으로 미디어월 스크린 및 모든 접속 노트북에 실시간 등장합니다.
2. **배경 테마 실시간 전환 (`theme_change`)**:
   - 마스터 관리자 패널에서 배경 테마를 변경하면 미디어월 대형화면이 실시간 크로스페이드로 전환됩니다.
3. **전시 설정 실시간 동기화 (`config_update`)**:
   - 최대 동시 표시수(**기본 12개**), 캐릭터 체류 수명(15분) 등이 전 기기에 일괄 적용됩니다.
4. **캐릭터 퇴장 및 전체 초기화 (`character_remove`, `clear_all`)**:
   - 관리자의 강제 퇴장 명령이 모든 화면에서 동기화됩니다.

### 2. SQLite 파일 기반 경량 DB (`data/media_wall.db`)
- **데이터 보존**: 호스트 노트북의 서버를 종료하거나 재부팅해도 **현재 적용된 테마**, **전시운영 설정값(최대 표시수 12개 등)**, **화면에 살아있는 캐릭터 목록**이 SQLite 데이터베이스 파일(`data/media_wall.db`)에 영구 저장됩니다.
- 서버 재시작 시 자동으로 DB 상태를 불러와 이전 전시 상태를 100% 복구합니다.

## 🔒 사설 IP 환경의 Service Worker(HTTPS) 대응 완벽 가이드

### ⚠️ 문제 배경
구글 크롬, 마이크로소프트 엣지 등 최신 브라우저는 보안 정책상 `localhost`가 아닌 사설 IP(`http://192.168.x.x:포트`)로 접속할 경우 **비보안 출처(Insecure Origin)**로 취급하여 **Service Worker(오프라인 캐싱 및 PWA 기능)**를 비활성화합니다.

본 프로젝트는 현장 상황에 맞춰 **3가지 해결 방법**을 제공합니다:

---

### 방법 A: mkcert를 이용한 완벽한 로컬 HTTPS 구성 (가장 추천 ⭐)

호스트 노트북에서 `mkcert`를 이용해 공인 Root CA 인증서를 발급하면, 브라우저의 보안 경고 없이 안전한 HTTPS(`https://192.168.x.x:3443`) 환경에서 Service Worker가 100% 활성화됩니다.

#### 1) mkcert 설치 (호스트 노트북)
- **Windows (Chocolatey 사용 시)**:
  ```bash
  choco install mkcert
  ```
- **Windows (수동 다운로드)**:
  [mkcert GitHub Releases](https://github.com/FiloSottile/mkcert/releases)에서 `mkcert-vX.X.X-windows-amd64.exe` 다운로드 후 `mkcert.exe`로 이름 변경하여 `C:\Windows\System32`에 복사합니다.
- **Mac (Homebrew)**:
  ```bash
  brew install mkcert
  ```

#### 2) 로컬 CA 등록 및 인증서 발급
호스트 노트북의 프로젝트 폴더에서 아래 명령어 또는 `scripts/generate-cert.bat`을 실행합니다:

```bash
# 1. 로컬 신뢰 루트 CA 등록
mkcert -install

# 2. 호스트 IP와 localhost를 포함한 인증서 생성 (예: 호스트 IP가 192.168.0.225인 경우)
mkcert -key-file certs/key.pem -cert-file certs/cert.pem localhost 127.0.0.1 192.168.0.225
```

#### 3) 서버 실행 및 접속
```bash
npm run start
```
이제 10대의 노트북에서 `https://192.168.0.225:3443`으로 접속하면 Service Worker가 정상 동작합니다!

> **팁**: 학생 노트북에서도 인증서 경고를 없애려면 호스트의 `mkcert -CAROOT` 경로에 있는 `rootCA.pem` 파일을 학생 노트북에 복사하여 '신뢰할 수 있는 루트 인증 기관'에 등록해두면 모든 기기에서 초록색 자물쇠가 뜹니다.

---

### 방법 B: 브라우저 보안 플래그 설정 (인증서 발급 없이 간편 설정 🚀)

각 노트북의 브라우저에서 호스트 사설 IP를 '보안 출처'로 등록하는 방법입니다. 인증서 설치가 번거로울 때 1분 만에 적용할 수 있습니다.

1. 학생/전시 노트북의 크롬 또는 엣지 브라우저를 엽니다.
2. 주소창에 다음 주소를 입력하고 Enter를 누릅니다:
   - **Chrome**: `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
   - **Edge**: `edge://flags/#unsafely-treat-insecure-origin-as-secure`
3. 해당 항목을 **`Enabled`**로 변경합니다.
4. 아래 텍스트 입력창에 호스트 서버 주소를 입력합니다:
   ```text
   http://192.168.0.225:3000
   ```
   *(※ 본인의 호스트 IP로 변경)*
5. 브라우저 우측 하단의 **`Relaunch` (다시 시작)** 버튼을 클릭합니다.
6. 이제 `http://192.168.0.225:3000` 접속 시 HTTP 환경에서도 Service Worker가 즉시 활성화되어 오프라인 캐싱이 동작합니다!

---

### 방법 C: 일반 HTTP 모드 무설정 사용 (기본 지원)

- 별도의 HTTPS 인증서나 브라우저 플래그를 설정하지 않더라도, **Socket.io 실시간 동기화, SQLite 데이터 저장, 대형 미디어월 화면, 드로잉 스튜디오, 마스터 관리자 등 모든 기능은 100% 정상 작동**합니다.
- Service Worker 등록 에러는 콘솔에 조용히 안내 로그만 남기며 앱 실행에 일절 지장을 주지 않도록 안전하게 예외 처리되어 있습니다.

## 🛠️ 방화벽 및 네트워크 트러블슈팅

### 1. 학생 노트북에서 접속이 되지 않을 때 (무한 로딩)
호스트 노트북의 **Windows Defender 방화벽**이 Node.js 포트를 차단하고 있을 수 있습니다:
1. `Windows Defender 방화벽` -> `고급 설정` 실행
2. `인바운드 규칙` -> `새 규칙...` 클릭
3. `포트(O)` 선택 -> `TCP`, 특정 로컬 포트에 `3000, 3443` 입력
4. `연결 허용` 선택 -> `도메인`, `개인`, `공용` 모두 체크 후 저장 (규칙 이름: `MediaWall Port`)

### 2. Wi-Fi 공유기 AP 격리(AP Isolation) 확인
일부 학원/전시장 공유기는 기기 간의 통신을 차단하는 **AP Isolation(클라이언트 격리)** 기능이 켜져 있을 수 있습니다. 공유기 관리자 페이지에서 해당 옵션이 **비활성화(Off)**되어 있는지 확인하세요.

## 📁 주요 프로젝트 파일 구성

- **`server.js`**: Express, Socket.io, WebSocket, SQLite, HTTP/HTTPS 이중 서빙 호스트 서버
- **`database.js`**: `better-sqlite3` 기반 경량 데이터베이스 영구 저장 모듈
- **`public/sw.js`**: 오프라인 PWA 서비스 워커 (Socket.io/API 네트워크 분기 캐싱)
- **`public/js/network.js`**: 10대 노트북 양방향 실시간 동기화 클라이언트 모듈 (Socket.io)
- **`scripts/generate-cert.js`**: 로컬 IP SAN 지원 자동 SSL 인증서 생성 스크립트
- **`start-server.bat`**: 윈도우 1-클릭 서버 실행 스크립트
- **`data/media_wall.db`**: SQLite 영구 데이터베이스 파일 (자동 생성)
- **`certs/`**: SSL 인증서 보관 디렉터리 (`cert.pem`, `key.pem`)
